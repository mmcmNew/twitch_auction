# Twitch Auction (Implementation Start)

Backend MVP для сервиса интерактивных аукционов/голосований на Twitch.


## Что уже реализовано


- Внутренняя архитектура backend постепенно разделяется на слой API и доменные сервисы (`app/services.py`) для упрощения расширения и тестирования бизнес-правил.
- Часть логики вкладов/сигналов (`расчёт итогового вклада`, `порог крупного вклада`, `смена лидера`) вынесена в сервисный слой для повторного использования и unit-тестов.
- В сервисном слое добавлены утилиты для UI-контекста (`build_stream_embed_url`) и общих ограничений пагинации/лимитов (`clamp_limit`).
- FastAPI API с SQLite-хранилищем.
- Ошибки API стандартизированы в единый формат `{code, message, details}` для упрощения frontend-интеграции.
- Локальная авторизация без Twitch:
  - `POST /auth/register` (email/password) для регистрации тестового аккаунта;
  - `POST /auth/login` для получения Bearer токена;
  - защищённые операции поддерживают либо `X-User-Login`, либо `Authorization: Bearer <token>`.
- Списковые endpoint’ы поддерживают базовые фильтры/лимиты для UI (`GET /auctions` по каналу/статусу, `GET /history/auctions` по каналу).
- Аукционы и позиции:
  - создание/просмотр аукционов;
  - запуск и завершение аукциона;
  - добавление и сортировка позиций.
- Предложения зрителей:
  - создание предложения;
  - модерация (approve/reject);
  - автосоздание позиции при approve.
- Баланс и вложения:
  - пополнение кошелька зрителя в рамках аукциона;
  - просмотр кошелька;
  - вложение баллов в позицию с проверкой доступного баланса;
  - история вложений по аукциону.
- История аукционов:
  - список завершённых аукционов с победителем и суммой вложений;
  - детальный просмотр завершённого аукциона с отсортированными позициями.
- Перенос аукционов:
  - `POST /auctions/{id}/clone` для запуска нового аукциона на базе прошлого;
  - `POST /auctions/{id}/restart` для перезапуска завершённого аукциона (опционально сразу active);
  - поддержка переноса баллов и частичного сброса по выбранным позициям.
- UI-поддержка для стрима и эффектов:
  - `GET /auctions/{id}/activity` для ленты последних действий (вклады, модерация, этапы финализации);
  - `GET /auctions/{id}/ui-context` для таймера окончания и embed-ссылки на плеер стрима;
  - `GET /auctions/{id}/effects` для триггеров UI-эффектов (смена лидера, крупный вклад, новое действие, скорое завершение).
  - `GET /auctions/{id}/events` SSE-поток снапшотов для автообновления UI в реальном времени.
- Завершение аукциона с промежуточными стадиями:
  - `active -> locked` (вклады останавливаются);
  - запуск/завершение рулетки (`roulette_running`);
  - фиксация победителя и перевод в `closed`.
- Рулетка при внесении баллов:
  - отдельный endpoint вклада со случайным множителем;
  - в истории вклада сохраняются `base_amount`, `multiplier`, `amount`.
- Антиспам предложений:
  - лимит предложений на автора в рамках одного аукциона (3 в час).
- Audit log:
  - логируются ключевые действия модерации и финализации аукциона;
  - доступен endpoint просмотра журнала `GET /audit-log`.
- Роли по каналу (без жёсткой привязки к первой авторизации):
  - один и тот же пользователь может быть стримером в своём канале и зрителем/модератором в другом;
  - модератор может модерировать предложения и одновременно голосовать своими баллами.
- Награды канала:
  - настройки набора наград для пополнения баланса через `reward-presets`;
  - при запуске аукциона создаются награды для активного набора (или дефолт `5k/10k/50k/100k`).

## Ролевой доступ

Для защищённых endpoint'ов используется заголовок `X-User-Login`.

- `streamer`: запуск аукциона, настройка наград.
- `streamer`/`moderator`: создание аукциона, закрытие, управление позициями, модерация предложений.
- `viewer`: может участвовать через кошелёк и вложения.

## Frontend (следующий этап): React + PWA + mobile-first

Планируемый UI стек:
- React + TypeScript (в текущем спринте старт через Vite)
- TanStack Query
- PWA через service worker/Workbox

Ключевые требования к UI:
- mobile-first адаптация (телефон в приоритете);
- встроенный Twitch player + голосование на одном экране;
- лента последних действий (`/auctions/{id}/activity`);
- таймер/сигналы завершения (`/auctions/{id}/ui-context`);
- эффекты: смена лидера, крупный вклад, скорое завершение.

## UI MVP (React + PWA readiness)

В репозитории добавлен `frontend/` (Vite + React + TypeScript) со стартовыми экранами:
- `/viewer` — экран зрителя (стрим + таблица + лента действий);
- `/dashboard` — базовый экран стримера/модератора;
- `/overlay` — компактный режим для OBS.

Что уже подключено в UI:
- чтение API backend (`/auctions`, `/positions`, `/activity`, `/ui-context`, `/effects`);
- автообновление через SSE (`/auctions/{id}/events`) с invalidation кэша;
- mobile-first вёрстка;
- PWA-база через `vite-plugin-pwa` (manifest + service worker).

Локальный запуск UI:

```bash
cd frontend
npm install
npm run dev
```

UI доступен на `http://127.0.0.1:5173`.

### Как потестировать UI без подключения backend

Можно включить mock-режим (локальные данные):

```bash
cd frontend
VITE_USE_MOCKS=1 npm run dev
```

В этом режиме:
- UI не делает запросы к backend;
- SSE не подключается;
- таблица/активность/эффекты берутся из `frontend/src/mockData.ts`;
- в интерфейсе отображается плашка `Mock mode`;
- блок «Тестовый режим: проверка сервера» вернёт mock-ответ для `/health`.

Это удобно для проверки верстки, роутов и базового UX даже без API.


### Проверка доступности сервера из UI

В любом режиме можно нажать кнопку `Проверить сервер (/health)` в карточке
`Тестовый режим: проверка сервера`.

- Если backend доступен, UI покажет `✅`, latency и JSON-ответ `/health`.
- Если backend недоступен, UI покажет `❌` и текст ошибки.
- В mock-режиме вернётся локальный ответ `{ "status": "ok", "mode": "mock" }`.
